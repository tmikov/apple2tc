# Apple II+ machine state at the BASIC prompt, after boot, with no program
# loaded. Game-independent: this is the floor any program started from the
# prompt begins on.
#
# WHY IT EXISTS
#
# A decompiled game starts at the reset vector and boots through the ROM,
# because that is what the recording did -- which makes every byte of ROM the
# boot path touches reachable code the decompiler must emit. For Snake Byte
# that is 1074 of 1171 tracked sites, against 97 for the game itself.
#
# Retargeting the entry to the start address of the program itself deletes all
# of it (measured for Snake Byte: 1,530 blocks deleted, leaving 4). The obstacle
# is that the program does not start on a blank machine: boot set up the text
# window, the output vector, the stack and part of zero page, and the program
# reads all of that without ever writing it.
#
# This is that state, recorded once.
#
# REGENERATE WITH
#
#   decoded/rom/make-boot-state.sh [build-dir]
#
# which captures with:
#
#   a2run --frames=200 --snapshot-at=FD1B --snapshot-out=boot.bin
#
# $FD1B is the KEYIN wait loop: the first time the machine asks for a keystroke
# is the moment boot has finished and nothing else has happened. The snapshot
# is one-shot and fires on first arrival; it also writes boot.bin.regs.
#
# WHAT IS DELIBERATELY NOT LISTED
#
#   Unwritten memory. RAM comes up as $FF and the text screen as $A0. Only
#   departures from those fills are below. The rest is not state, it is what
#   unwritten memory happens to read as.
#
#   $D000-$FFFF, ROM. Identical by construction.
#
# CAVEAT
#
# This is the state at the prompt, before anything is typed. A program reached
# by typing a command has had it echoed and parsed, which edits the input
# buffer and moves the cursor. Those deltas are per-program; this is the common
# floor underneath them.

REGISTERS at $FD1B
  A=A0  X=00  Y=01  SP=F0  STATUS=A0   (cycles since reset: 141504)

SOFT SWITCHES
-------------
  These are not memory -- they live in the host IO emulation, so no RAM
  image carries them. A rebased entry point must set them explicitly.

  vid_control = $01   text, page 1, not mixed
  keyboard      last key read $00, 0 queued

  Text, page 1, not mixed is the power-on state: the ROM never touches the
  graphics switches on a boot that reaches the prompt.
