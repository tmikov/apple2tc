# Splitting system2-inc.h Implementation Plan

**Goal:** Let a program built on the `--irc1` engine have more than one translation unit. Today `system2-inc.h` *defines* the emulated machine, so every program is one file — which is why `snake-byte.c` is 5,322 lines with the Apple II ROM welded into it.

**Architecture:** Split the header into declarations and definitions. State becomes `extern`; the trivial accessors stay in the header as `static inline` so nothing at a call site gets slower; the substantial functions move to a real `.c`. `system2-inc.h` survives as a shim that includes both, so today's single-TU users compile unchanged.

**Tech Stack:** C11, CMake + Ninja.

## Global Constraints

- **`system-inc.h` is not touched.** Its four users are single generated files (`robotron.c`, `bolo.c`, `rom.c`, `as-generated/snake-byte-simple-c.c`), none of which wants a second TU, and it has no `emulated_entry_point` hook. If some later step forces a shared-interface change, that would be a small edit there, never a split.
- Every task ends with: a full `ninja -C cmake-build-debug` (93 targets, 0 errors), `tests/run-tests.sh`, and all three gates — snake-byte `probe-acceptance.sh` (31 PASS), snake-byte `verify.sh` (4 PASS), rom `probe-acceptance.sh` (2 PASS).
- Generated files under `decoded/snake-byte/reference/` are regenerated by `scripts/decompile.sh`, never hand-edited. The gate's `[regen]` check enforces this and runs first.
- `decoded/snake-byte/snake-byte.c` is hand-owned. Use `scripts/codegen-fingerprint.sh` to show when a change to it emitted identical code.

## Where things end up

| | |
| --- | --- |
| `include/apple2tc/a2machine.h` | `extern` state, `static inline` accessors, the `CYCLES` macros, declarations of the rest |
| `include/apple2tc/a2machine.c` | the state's definitions, and every function that is not a one-liner |
| `include/apple2tc/system2-inc.h` | `#include` of both — the compatibility shim |

**What stays inline, and why it is not a judgement call:** every accessor is one
to three lines over the machine's state — `peek`, `poke`, `peek_zpg`,
`poke_zpg`, `peek16`, `peek16_zpg`, `peek16al`, `push8`, `pop8`, `push16`,
`pop16`, `ram_poke_impl`. They belong in the header as `static inline` because
they are accessors. Each TU gets its own copy of the code and they all share one
machine, which is exactly right.

Measured beforehand, so nobody has to wonder: forcing those eleven out of line
in the reference build changed a 40,000-frame run from 2.50/2.48/2.48 s to
2.51/2.51/2.47 s. The emulated machine is not the bottleneck. That measurement
is *not* the reason to keep them inline — it is the reason not to agonise about
where the rest of the line falls.

**What moves to the `.c`:** `adc_decimal` and `sbc_decimal` (~23 lines each),
`cycles_expired`, `emulated_thread`, `run_emulated`, `shutdown_emulated`,
`engine_stop_reason`, `engine_parse_arg`, `engine_print_help`, and the ABI
wrappers `ram_peek`, `ram_poke`, `ram_peek16`, `ram_peek16al`, `get_regs`,
`set_regs`, `reset_regs`, `get_cycles`, `get_ram`. Those last nine are declared
in `a2engine.h` and called by the host by name, so they need external linkage
and cannot be `static inline` — but the header already shows the pattern:
`ram_poke` is a one-line wrapper over the inline `ram_poke_impl`.

**What the header keeps as macros:** `CYCLES` and `CYCLES_EDGE`. `CYCLES`
expands to a reference to `branchTarget`, a *local* variable in generated code,
so it can never become a function.

### Task 1: `emulated_entry_point` gains external linkage

**Files:** `include/apple2tc/system2-inc.h`, `tools/apple2tc/IRC1.cpp`,
`decoded/snake-byte/snake-byte.c`, and by regeneration everything in
`decoded/snake-byte/reference/`.

This is the one interface change the split forces, and it is a prerequisite:
`emulated_thread` calls `emulated_entry_point`, so once the former lives in
another TU the latter cannot be `static`. Doing it first keeps it out of the
larger diff.

- [ ] **Step 1:** in `system2-inc.h`, change the forward declaration at line 219
      from `static void emulated_entry_point(void);` to
      `void emulated_entry_point(void);`.

- [ ] **Step 2:** in `tools/apple2tc/IRC1.cpp` line 118, change the emitted text
      from `static void emulated_entry_point(void) {` to
      `void emulated_entry_point(void) {`.

- [ ] **Step 3:** in `decoded/snake-byte/snake-byte.c` around line 261, drop the
      `static` from its definition.

- [ ] **Step 4: regenerate.** From `decoded/snake-byte`:
      `./scripts/decompile.sh ../../cmake-build-debug`. Every file under
      `reference/` should change by exactly this one word; read the diff and
      confirm nothing else moved.

- [ ] **Step 5: full verification** (see Global Constraints), then commit.

### Task 2: `a2machine.h` — the declarations

**Files:** create `include/apple2tc/a2machine.h`; `system2-inc.h` untouched for now.

- [ ] **Step 1:** create the header with the include guard and the same includes
      `system2-inc.h` has today: `probe.h`, `system.h`, `c11threads/c11threads.h`,
      `<assert.h> <stdio.h> <stdlib.h> <string.h>`.

- [ ] **Step 2: the state, as `extern`.** `s_pc`, `s_a`, `s_x`, `s_y`, `s_sp`,
      the seven `s_status_*`, `s_ram[0x10000]`, `s_cycles`,
      `s_remaining_cycles`, `g_debug`, and the coroutine's `s_initialized`,
      `s_emu_thread`, `s_emu_cond`, `s_emu_mutex`, `s_emu_enabled`.

      `g_debug` is already declared `extern uint8_t g_debug;` in `a2engine.h`,
      so do **not** redeclare it — include is enough.

- [ ] **Step 3: the accessors, copied verbatim as `static inline`.** The eleven
      named above plus `ram_poke_impl`. Their bodies do not change at all; only
      the storage they read is now `extern`.

- [ ] **Step 4: the macros**, `CYCLES` and `CYCLES_EDGE`, copied verbatim.

- [ ] **Step 5: declarations** for everything moving to the `.c`, plus
      `struct ResAndStatus` and `void emulated_entry_point(void);`.

- [ ] **Step 6:** nothing includes it yet, so verification is that it compiles
      standalone:
      `cc -I include -std=gnu11 -fsyntax-only -x c include/apple2tc/a2machine.h`
      Then commit.

### Task 3: `a2machine.c` — the definitions

**Files:** create `include/apple2tc/a2machine.c`.

Placing a `.c` under `include/` is odd but deliberate: it is the other half of a
header that lives there, and splitting the pair across directories would hide
that. Say so in its file comment.

- [ ] **Step 1:** `#include "apple2tc/a2machine.h"`, then the state definitions
      with their initialisers exactly as they are now — including
      `s_status_not_z = 1` and `s_emu_enabled = 0`, which are not zero.

- [ ] **Step 2:** move the non-inline function bodies, verbatim.

- [ ] **Step 3:** verify it compiles alone:
      `cc -I include -std=gnu11 -c include/apple2tc/a2machine.c -o /tmp/a2m.o`

      It will not *link* alone — `emulated_entry_point` is supplied by each
      program — which is correct and expected.

- [ ] **Step 4:** commit. Nothing uses it yet.

### Task 4: `system2-inc.h` becomes the shim

**Files:** `include/apple2tc/system2-inc.h`.

- [ ] **Step 1:** replace its whole body with:

```c
#include "apple2tc/a2machine.h"
#include "apple2tc/a2machine.c"
```

      and a comment saying what it is: the single-translation-unit form, kept so
      that existing programs compile unchanged. A program either includes this
      **or** includes `a2machine.h` and links `a2machine.c` — never both, or the
      definitions appear twice.

- [ ] **Step 2:** this is the moment the whole change is either right or wrong,
      because every existing user now goes through the new files. Run the full
      verification. Also run `scripts/codegen-fingerprint.sh` in
      `decoded/snake-byte` and compare against the value before Task 1: the
      emitted code should be **identical**, since nothing about the program
      changed — only where its text lives.

- [ ] **Step 3:** commit.

---

### Task 5: prove separate compilation actually works

**Files:** `decoded/snake-byte/CMakeLists.txt`, a scratch second source.

A shim that compiles is not evidence the goal was met. The goal was two
translation units.

- [ ] **Step 1:** convert the `snake-byte` target: `snake-byte.c` includes
      `apple2tc/a2machine.h` instead of `apple2tc/system2-inc.h`, and the target
      gains `${A2TC_INC}/a2machine.c` as a source.

- [ ] **Step 2:** add a second, trivial TU to that target — a file with one
      function that calls `ram_peek(0)` and returns it, called from nowhere.
      It must compile and link. That is the property this whole plan exists for,
      and until something does it, nothing has demonstrated it.

- [ ] **Step 3:** full verification. `snake-byte-run` must still be ~269 KB and
      still start at the game rather than booting — the check that caught a
      wrong-target link once already.

- [ ] **Step 4:** delete the scratch TU, keep the two-source arrangement, and
      commit.

## What this unlocks, and is not doing

Splitting the Apple II ROM routines out of `snake-byte.c` — 682 lines, 12% of
the file, a clean layer with one upward call — becomes a normal `.c` file
instead of a textual `#include`. That is a separate plan and should stay one.

## Risks

- **Duplicate definitions** if any program both includes the shim and links
  `a2machine.c`. The linker says so loudly; there is no silent form.
- **A missed initialiser.** `s_status_not_z = 1` is the one that is not zero and
  would fail quietly-ish — the gates would catch it, but read the diff.
- **Regeneration drift** in Task 1: if `decompile.sh` rewrites more than the one
  word, stop and find out why before committing.
