The same machine reports two different page numbers depending on which tool you
ask.

`a2_io_get_vidpage_index()` returns a 0-based index (0 or 1). Two callers
disagree about how to present it:

- `lib/a2mcp/mcp_machine.cpp:205` puts it in `status` verbatim, so a2mcp says
  `"page": 1` for hi-res page two.
- `lib/a2host/probe.c:161` writes `index + 1` into the `--snapshot-out` `.regs`
  sidecar, so a2run says `vidpage 2` for the very same state.

Measured on Neptune, both at `vid_control $0C`:

    a2run  --snapshot-at=...  ->  vidpage 2
    a2mcp  status             ->  "page": 1

This is not cosmetic. `docs/neptune.md` records "frame 1400, `hgr` page 1" --
correct in a2mcp's numbering, and read as a contradiction by anyone who then
captures a snapshot and sees `vidpage 2`. That happened during this session and
cost a wrong "the doc is stale" conclusion before the numbering was checked.

Pick one convention and use it in both places. 1-based matches how the hardware
is spoken about (HGR page 1 at $2000, page 2 at $4000) and matches the `.regs`
sidecar's neighbours, which are all human-facing decoded values; 0-based matches
the accessor's return. Either is defensible, both is not.
