--code-at takes 'origin target' pairs and requires the instruction at origin to
be a branch:

    FATAL: --code-at: the instruction at origin $1060 is not a branch. Only
    RTS, RTI, JMP, JSR and conditional branches can be given extra targets

That rules out the case a self-modifying game actually presents. Neptune picks
its input device once at the title screen and then WRITES its input routines.
$3700 stores the bytes 20 B0 36 4C 80 11 into $1060, so in joystick mode $1060
is `JSR $36B0 / JMP $1180` and $36B0 is a 50-byte paddle reader. In the image
as captured, $1060 holds `AD 00 C0` -- the keyboard arm -- so:

  - the tracer never sees a reference to $36B0, and emits all of it as DFB;
  - --code-at cannot assert the edge, because the origin is a load, not a
    branch.

There is no way to express "this address is code, reached by a path that only
exists after the program rewrites itself". The listing therefore silently omits
an entire input mode, and a hardware surface derived from it omits $C070 and
$C064 -- which is exactly how decoded/neptune/README.md came to publish a wrong
surface.

Proposal: accept a single-address line in the --code-at file, meaning "start
disassembling here as a root, no incoming edge asserted". It is the same file,
the same 'every line carries its argument' convention, and it does not weaken
the existing check on paired lines. An unreferenced root is exactly what
self-modified code looks like from the tracer's point of view.
