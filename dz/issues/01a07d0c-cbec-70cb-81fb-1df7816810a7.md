`a2host.c`'s `print_help()` advertises:

    --count-bt       Count branch targets

but no branch of `a2host_parse_args()` matches `--count-bt`. The only
occurrence of the string in the tree is the `printf` itself.

So the argument falls through the host parser to `engine_parse_arg()`, which
does not claim it either, and the front end responds by printing its help and
exiting. A user following `--help` gets help back instead of the feature.

Reproduce:

    a2run --frames=40 --count-bt        # prints --help, runs nothing

Found while looking for a way to locate Neptune's main loop; the job was done
with `--collect` instead.

Either implement it (`DebugCountBB` already exists in a2engine.h and looks like
the intended mechanism) or delete the line from `print_help()`. The second is a
one-line change and is honest; the first is what the help currently promises.

Worth a moment either way for the general case: a help text listing an option
the parser does not accept is a lie that no test currently catches, and there
may be others. A test that feeds back every option `--help` mentions and
requires the binary not to respond with help would catch the whole class.
