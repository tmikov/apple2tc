--routines-report prints a rejection as, e.g.:

    REJECT $1B80  terminator JmpInd
      walked 39 block(s): $1B80 $1B88 $1B8C ... $1C46

The reason names the *kind* of terminator that caused the rejection but not the
block it is in, and the walked set is often dozens of blocks spanning several
kilobytes. For Neptune's $0E00 the walk is 152 blocks over $0E00-$2E05, and
finding the offending block means re-deriving the walk by hand.

It also matters for diagnosis, not just convenience. $0E00 is rejected with
"terminator JmpInd", which reads as "this routine ends in an indirect jump" --
but $0E00's own terminators are eight RTS and five direct JMPs. The JmpInd is
$218F, reached only because a tail JMP at $0EA6 transfers into a different
region entirely. The printed reason invites the wrong conclusion about which
code is the problem, and in this repository it produced exactly that: a
committed document explained the rejection as control running past the
routine's RTS, when RTS at depth 0 correctly ends the walk and the leak is
through a direct JMP.

Every reject() call site has the block in hand. Printing its address costs one
format argument and turns a 152-block search into a lookup.
