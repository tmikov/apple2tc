`lib/a2io` implements nothing between `$C060` and `$C07F`. Every read falls
through `a2_io_peek()`'s `default:` arm, which returns 0 and prints
`Unsupported IO location read $%04X` to stderr -- once per access.

Neptune uses all of it. It supports keyboard *and* joystick control and picks
whichever you touch first, patching three call sites between the two
(`$35A2` installs the keyboard reads, `$3736` installs `JSR $36B0`). Measured
over a 100-second run that took the joystick branch:

```
$C061 rd=1805    button 0
$C062 rd=3103    button 1
$C064 rd=1293    PADDL0
$C065 rd=1293    PADDL1
$C070 rd=2586    PTRIG
```

`$C070` is read exactly twice per pair of paddle reads: the standard sequence
is trigger, then spin on `PADDLn` counting iterations until bit 7 drops. Since
`PADDLn` returns 0, bit 7 is never set and the loop exits on its first read with
a count of zero -- 1,293 reads for 1,293 triggers, one apiece. The stick reads
pinned to a corner.

Holding `$C061` high is enough to leave the title screen: the frame hash
diverges from baseline at frame 1282 and the playfield appears.

```
a2run --disk1=dsk/Neptune.dsk --headless --frames=6000 --no-sound
```

This is a missing feature, not the cause of the keyboard bug filed alongside it
-- Neptune's keyboard path works, and a keypress starts the game just as well.
But nothing in the tree can drive an Apple II game that wants an analog stick,
and any such game floods stderr while it tries.

## Wanted

Game-port state in `a2_iostate_t` -- three pushbuttons and four paddles -- and
the reads that go with them:

- `$C061`-`$C063` (PB0-PB2): bit 7 set while the button is down.
- `$C070` (PTRIG): start the one-shots.
- `$C064`-`$C067` (PADDLn): bit 7 set until the paddle's timer expires. The
  figure the ROM's `PREAD` loop is calibrated against is about 11 cycles per
  count over a 0-255 range; getting that constant right is most of the work,
  since a program that rolls its own read loop rather than calling `PREAD` will
  notice.

Plus a host-side way to set them, in both front ends -- something a live player
can use in `a2emu`, and something `--key-file`/probe-driven runs can use so a
joystick game can be replayed headlessly at all.

Also worth fixing regardless: the `default:` arm prints to stderr on every
access. A game polling an unimplemented switch 60 times a second makes the
console unusable. It should be rate-limited, or report once per address.

    The stderr flood is dealt with: $C060-$C07F now has its own arm in a2_io_peek that returns the same zero without reporting the access, and tests/a2io pins the silence. A 6000-frame Neptune run goes from 3,072 lines to none.

    The port itself is still unemulated, which is what this issue is for. Reading zero is an answer, not an abstention -- no button held, and a paddle one-shot that has already expired -- so a program offering joystick control still believes it has one, and now does so quietly.
- 2026-09-08T07:05:35.594Z  Tzvetan Mikov <tmikov@gmail.com>  comment
    The game port is implemented: three pushbuttons, four paddle one-shots timed at 11 cycles per count against an extended 64-bit clock, and the $C068-$C06F mirror. a2emu drives PADDL0/PADDL1 and the buttons from the arrow keys behind an F7 mode toggle. Calibrated against the ROM's PREAD rather than against its own arithmetic; see tests/gameport/. Replay is still out of scope -- joystick input is ignored during a --key-file replay and is not recorded.
